# BPMN Generator

Инструмент для автоматической генерации BPMN 2.0 диаграмм из текстового описания бизнес-процессов.

Вы описываете процесс в структурированном текстовом файле → получаете готовую BPMN-диаграмму, которую можно открыть в браузере или редакторе.

---

## Как это работает

```
Текстовый файл (.txt)
        ↓
parse_process.py — разбирает текст, создаёт process.json
        ↓
generate_bpmn.py — генерирует process.bpmn из JSON
        ↓
validate_bpmn.py — проверяет корректность диаграммы
        ↓
Открываете process.bpmn на bpmn.io
```

Управление происходит через **OpenCode** — вы пишете команды на русском языке, OpenCode сам вызывает нужные скрипты.

## Запуск через OpenCode

Откройте папку проекта в OpenCode. Дальше пишите команды на русском:

**Шаг 1 — разобрать процесс:**
```
Разбери процесс из файла examples/process_report.txt
```

**Шаг 2 — сгенерировать диаграмму:**
```
Сгенерируй BPMN диаграмму
```

OpenCode автоматически запустит генерацию и валидацию. Если валидация найдёт ошибки — скажет об этом и предложит исправить.

**Шаг 3 — открыть диаграмму:**

Перейдите на https://bpmn.io/ → нажмите иконку папки → откройте файл `output/process.bpmn`

Или скачайте Camunda Modeler: https://camunda.com/download/modeler/

## Редактирование диаграммы

Через OpenCode — текстовыми командами:
```
Добавь шаг "Проверить договор" после задачи "Отправить на согласование"
Удали шлюз "Изделие из прайса?" и соедини напрямую
Добавь участника "Юрист" и задачу "Согласовать условия"
Переименуй задачу "Внести изменения" в "Доработать калькуляцию"
```

Визуально — откройте `output/process.bpmn` в Camunda Modeler и редактируйте мышкой.

## Формат входного файла

Файл должен быть в кодировке UTF-8 и содержать три секции:

```
БИЗНЕС-ПРОЦЕСС: Название процесса
============================================================

УЧАСТНИКИ:
  - Имя участника (lane_id)
  - Другой участник (lane_other)

ЭЛЕМЕНТЫ ПРОЦЕССА:
  [startEvent] Название стартового события → Участник
  [task] Название задачи → Участник
  [exclusiveGateway] Вопрос для ветвления? → Участник
  [endEvent] Название завершающего события → Участник

ПОТОКИ:
  Источник --> Цель
  Источник --> Цель (условие перехода)
```

**Типы элементов:**

| Тип | Описание | Сколько |
|-----|----------|---------|
| `startEvent` | Начало процесса | Ровно 1 |
| `endEvent` | Завершение процесса | 1 или больше |
| `task` | Задача или действие | Любое количество |
| `exclusiveGateway` | Ветвление (если/или) | Любое количество |

**Правила потоков:**
- `Источник --> Цель` — простой переход
- `Источник --> Цель (Да)` — переход с условием (обязательно для шлюзов)
- Из каждого `exclusiveGateway` должно выходить минимум 2 потока с условиями

Пример готового файла: `examples/process_report.txt`

```

├── .opencode/
│   └── skills/
│       ├── parse_process.md    # Инструкция для OpenCode: разбор текста
│       ├── generate_bpmn.md    # Инструкция для OpenCode: генерация

│   ├── parse_process.py        # Текст → JSON (без API)
│   ├── generate_bpmn.py        # JSON → BPMN XML (без API)
│   ├── update_bpmn.py          # Редактирование JSON по запросу
│   └── validate_bpmn.py        # Проверка корректности BPMN (без API)
├── templates/
│   └── process.bpmn.j2         # Jinja2-шаблон BPMN 2.0
├── prompts/
│   └── parse_process.txt       # Системный промпт с few-shot примером
├── examples/
│   ├── process_report.txt      # Эталонный входной файл
│   └── bpmn_example.bpmn       # Эталонный корректный BPMN
├── output/                     # Результаты генерации
│   ├── process.json            # Промежуточный JSON
│   └── process.bpmn            # Готовая диаграмма
├── requirements.txt
└── README.md
```

## Что проверяет валидация

После каждой генерации автоматически запускается `validate_bpmn.py`. Он проверяет:

- XML синтаксически корректен
- Все элементы из JSON присутствуют в BPMN
- У каждой задачи есть входящие и исходящие потоки
- Нет висячих блоков (элементов без связей)
- Каждый шлюз имеет минимум 2 исходящих потока с условиями
- Все элементы находятся внутри своей дорожки (lane)
- Блоки не перекрываются
- Стрелки корректно соединены с элементами
- Структура загрузится в bpmn.io и Camunda без ошибок

Результат — JSON-отчёт, который OpenCode читает и сообщает вам что исправить.

## Возможные проблемы

**`pip` не найден** — Python не добавлен в PATH. Переустановите Python с галочкой "Add to PATH".

**Диаграмма не открывается в bpmn.io** — запустите валидацию и исправьте ошибки из отчёта.
